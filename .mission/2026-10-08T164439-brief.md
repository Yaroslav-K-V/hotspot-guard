# Analytics brief — feature/analytics

## Task 1: Add persistent connection analytics with History UI and CSV/JSON export

Goal: analytics — locally persisted uptime/outage stats, latency dynamics and
per-network breakdown shown in the History window, plus CSV/JSON export.

### Steps

1. TDD: write failing `Sources/hotspotguard-selftest/AnalyticsTests.swift`
   with `runAnalyticsTests()`, registered in `main.swift`. Cover:
   - `AnalyticsStore.record(sample:)` + queries: uptime fraction over a
     window, outage list with durations, latency p50/p95/max, per-SSID stats.
   - JSON file persistence round-trip through an injectable directory
     (temp dir in tests), age/count pruning.
   - `AnalyticsExport`: CSV and JSON output shape (header row, one row per
     outage/sample; valid JSON array).
2. Implement `Sources/HotspotGuardCore/AnalyticsStore.swift`:
   - `AnalyticSample` (timestamp, status, latencyMs, ssid), `Outage`
     (start, end, network), in-memory ring + JSON snapshot file in
     Application Support (injectable base URL), prune older than 30 days /
     beyond 5000 samples.
   - Pure query functions (uptime, outages, percentiles, perNetwork).
   - Follow repo conventions (swift-format 4sp/120col, SwiftLint clean,
     no dead code, no duplication over the 1% jscpd gate).
3. Wire recording into `ConnectionManager` via a defaulted
   `analytics:` recorder dependency: one sample per `performCheck()`,
   outage open on offline transition, outage close + per-network outcome on
   reconnect success/failure. Existing tests must keep compiling (defaulted
   parameter) and passing.
4. UI: extend `Sources/HotspotGuard/HistoryView.swift` with an Analytics
   section (uptime %, outages + total downtime, latency p50/p95, per-network
   rows, Export CSV / Export JSON buttons via save panel). `App.swift` passes
   the shared store. The History window must reference Analytics
   (reachability target).
5. Export: implement CSV/JSON writers in Core (pure, test-covered), wired to
   the History buttons.
6. Coverage-60 follow-up: add tests for currently uncovered but testable
   code until `./scripts/coverage.sh` passes — prime candidates:
   `DateFormatter+Extensions`, `LocationAuthorization` callbacks,
   `UserNotificationPresenter.present`, `PasswordStorage` migrate paths via
   `HOTSPOTGUARD_DEV_MOCK_KEYCHAIN=1`, `KeychainHelper` mock branches,
   `ConnectionManager` sleep/path edges. Do NOT game the gate (no exclusions
   to hit the number); if hardware-bound lines make 60% unreachable, stop
   and report the measurement instead.
7. Run the full gate: `swift build`, `swift run hotspotguard-selftest`
   (208+ new checks green), `format.sh --check`, `lint.sh` (0 serious),
   `dead-code.sh`, `check-test-layout.sh`, `duplicates.sh`,
   `generate-api-docs.sh` (+ commit regenerated docs), `check-agents-md.sh`,
   `flaky-check.sh`, `coverage.sh`.

### Reachability targets (must fail before, pass after)

- `test "$(grep -c 'Analytics' Sources/HotspotGuard/HistoryView.swift)" -gt 0`
- `grep -q 'runAnalyticsTests()' Sources/hotspotguard-selftest/main.swift`

### Constraints

- No push, no PR, no deletion of data, no credentials. Local branch only.
- Everything on-device: no network calls, no new hosts, no dependencies.
- EventLog rule ("never pass a password") extends to analytics: SSIDs are
  fine, passwords/secrets never recorded.
